# TPL-005: Architecture Note Template

Type: Template
Status: Active

Use this for a small architecture note. Keep it focused on the change or area being discussed. Use an ADR when the decision needs a durable record of options and trade-offs.

## Context

What is being built or changed, and why does it matter?

## System Boundary

What is inside this note, and what is outside it?

## Key Components

List the main parts involved and their responsibilities.

## Data Or Contracts

Name the important data, APIs, events, files, or interfaces.

## Security, Privacy, Accessibility, And Operations

Call out the practical concerns that need review.

## Decisions Needed

List the decisions that are still open.

## Risks Or Trade-Offs

Note the main risks, constraints, or trade-offs.

## Links

Add links to related standards, patterns, ADRs, designs, tickets, or review notes.
