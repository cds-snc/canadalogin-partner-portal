# Ownership And Updates

Use this guide to decide where an artifact should live and what should drive updates.

| Artifact class | Primary source | Local location | Derived or linked artifacts | Owner | Update trigger | Refresh or sync model |
|---|---|---|---|---|---|---|
| Delorean core guidance | Delorean core repo | Links from `docs/repo-guidance/`, agents, and skills | Local wrappers and starter docs | Delorean core owners | Core guidance changes | Link or summarize briefly; do not copy large docs; Delorean core is not the source of truth for solution code |
| Content audience classification | This template or solution repo | [docs/repo-guidance/docs-audience.md](docs-audience.md) | README indexes, docs folder shape, skill reference-loading rules | Solution repo maintainers | Docs grow, agent skills change, or humans report unclear reading paths | Keep human-primary docs few; route agent-loaded material through skills, agents, prompts, or repo-guidance files |
| Delorean adoption level | This template or solution repo | [delorean/config.yaml](../../delorean/config.yaml), [docs/repo-guidance/adoption-levels.md](adoption-levels.md) | Agents, scaffold profile, local verification expectations | Solution repo maintainers | The repo wants lighter or fuller Delorean process | Skills stay focused and level-agnostic; agents use the adoption level to decide which skills to invoke and which outputs are required |
| Shared architecture standards | `delorean_architecture`, aligned to Delorean core and reusable outside Delorean | `architecture_docs/standards/catalog.yml`, `architecture_docs/standards/README.md`, and `STD-*` IDs in generated solution repos | OpenSpec, OpenAPI, tests, evidence, local reference guides | Architecture guidance maintainers; solution repo maintainers for local adaptations | Technology choice, local workflow drift, or architecture guidance changes | Scaffold copies from `delorean_architecture`; use the catalog for routing; reference by ID and title; extend locally only for solution-specific needs |
| Shared baseline profiles | `delorean_architecture` | `architecture_docs/baselines/catalog.yml`, `architecture_docs/baselines/README.md`, `BAS-*` IDs, and baseline control profile YAML in generated solution repos | Control assessments, evidence bundles, release readiness, architecture notes, ADRs | Architecture guidance maintainers for reusable baselines; solution maintainers for local assessments | App type, release type, service context, or baseline control profile changes | Scaffold copies from `delorean_architecture`; reference by ID and title; record project-specific status in solution evidence, not in the reusable baseline |
| Reusable controls | `delorean_architecture` | `architecture_docs/controls/catalog.yml`, `architecture_docs/controls/README.md`, and control namespace IDs such as `GC-WEB-*` in generated solution repos | Baselines, standards impact, tests, evidence, release readiness | Architecture guidance maintainers for reusable controls; solution maintainers for local evidence | Government of Canada, CDS, departmental, security, privacy, platform, or program control expectations change | Scaffold copies from `delorean_architecture`; do not duplicate control detail locally; assess status and evidence in solution-owned records |
| Full-stack application stack decisions | `delorean_architecture`, with implementation in this template or solution repo | STD-003: Full-Stack Application Stack, [frontend/](../../frontend/), [backend/](../../backend/) | Frontend and backend standards, OpenSpec changes, tests, OpenAPI, local verification | Architecture guidance maintainers for the standard; solution maintainers for code | The accepted React/FastAPI stack, auth/session/data/tooling posture, or local setup changes | Make stack decisions explicit before code shape changes; keep local-safe defaults and block non-local work until the work context is known |
| Implementation and design patterns | `delorean_architecture` | `architecture_docs/patterns/catalog.yml`, `architecture_docs/patterns/README.md`, `PAT-*` IDs, and TPL-004: Pattern Template in generated solution repos | Standards, OpenSpec changes, ADRs, tests, evidence, starter examples | Architecture guidance maintainers; solution repo maintainers for local adaptations | Agents repeatedly implement the same scenario, standards are too abstract for implementation, or a common architecture pattern changes | Scaffold copies from `delorean_architecture`; use the catalog for routing; reference by ID and title; keep solution-specific variants clearly local |
| Reference architectures | `delorean_architecture` until adapted locally | `architecture_docs/architecture/reference/catalog.yml`, `REF-*` IDs when published, and local `docs/architecture/` notes only when a solution records a variation | Baselines, controls, ADRs, implementation plans, evidence | Architecture guidance maintainers for reusable reference architecture; solution architecture owners for local variations | A supported app type has a reusable architecture posture or a solution varies from that posture | Use the generated reference architecture catalog for routing; record material local variations in solution ADRs or baseline assessments |
| Work context standard | `delorean_architecture`; local assumption template remains in this template | STD-002: Work Contexts, [docs/templates/work-context-and-assumptions-template.md](../templates/work-context-and-assumptions-template.md) | OpenSpec change packages, prompts, agents, skills, control-boundary notes, evidence inputs | Architecture guidance maintainers; solution repo maintainers for local assumptions | Agents ask broad environment questions, work moves beyond localhost, data or secret rules change, or environment names change | Default to local developer / localhost when no environment is named; require named target and access path before shared-environment or production work |
| Database persistence standards and patterns | `delorean_architecture` | STD-020: Database Persistence, PAT-012: Alembic PostgreSQL Change, `architecture_docs/standards/catalog.yml`, and `architecture_docs/patterns/catalog.yml` in generated solution repos | Backend data models, repositories, migrations, seed scripts, tests, OpenSpec changes, evidence, and ADRs | Architecture guidance maintainers for reusable guidance; solution repo maintainers for local schema and data lifecycle decisions | Relational persistence, model, migration, repository, seed-data, stored-record, retention, delete, rollback, or data lifecycle expectations change | Scaffold copies from `delorean_architecture`; route by ID and title; record solution-specific ownership, retention, rollback, and evidence locally instead of copying source guidance |
| Government of Canada standards impact | `delorean_architecture`, aligned to official GC guidance and local policy needs | STD-017: Government of Canada Standards Review, STD-019: Government of Canada Web Application Baseline Governance, BAS-001: Government of Canada Web Application Baseline, TPL-003: Standards Impact Template, TPL-011: GC Web Application Baseline Assessment Template, `agent-configs/shared/skills/gc-standards/SKILL.md` source or `.github/skills/gc-standards/SKILL.md` generated target | Design packages, OpenSpec changes, implementation handoffs, tests, baseline assessments, evidence | Architecture guidance maintainers with standards reviewers; solution maintainers for local evidence | UI, accessibility, bilingual, security, privacy, IAM, IM, baseline, or evidence impact | Scaffold copies reusable guidance from `delorean_architecture`; record local exceptions, deferred controls, and assessment evidence clearly |
| Targeted GC review skills | This template or solution repo, aligned to Delorean core, official GC guidance, and selected public skill patterns | `agent-configs/shared/skills/gc-review-*` source; `.github/skills/gc-review-*`, `.agents/skills/gc-review-*`, or `.claude/skills/gc-review-*` generated targets | Standards impact blocks, verification findings, remediation tasks, evidence inputs for `delorean-evidence`, waiver needs, release-readiness context | Solution repo maintainers with standards reviewers | Accessibility, GC Design System, official languages, security, IAM, or IM review needs change | Keep as Delorean review/compliance procedures; do not redefine approvals, waivers, risk acceptance, or Evidence Bundle contracts |
| Local prompts | This template or solution repo | `agent-configs/vscode/prompts/` source; `.github/prompts/` generated target | Skills, agents, reference guides | Solution repo maintainers | Work-start flow changes | Update local prompt and related references |
| Local skills | This template or solution repo | `agent-configs/shared/skills/` and `agent-configs/codex/skills/` source; `.github/skills/`, `.agents/skills/`, or `.claude/skills/` generated targets as applicable | Agents, prompts for other tools, reference guides | Solution repo maintainers | Skill routing, local procedure, workflow entrypoint, or reference-loading changes | Keep `SKILL.md` thin and aligned with core; use `name` and `description` as the only frontmatter fields; keep detailed local and official reference lists in `references.md`; use `delorean-evidence` for Evidence Bundle assembly |
| Local agents | This template or solution repo | `agent-configs/vscode/agents/` source; `.github/agents/` generated target | Prompts, skills, phase routing, handoffs | Solution repo maintainers | Agent role, phase ownership, or handoff changes | Update `.agent.md` files, phase routing, handoffs, and references |
| Codex project instructions | This template or solution repo | `agent-configs/codex/AGENTS.md` source; `AGENTS.md` generated target for Codex scaffold targets | Skills, repo guidance, OpenSpec workflow, local verification | Solution repo maintainers | Codex repo operating rules, skill locations, control-boundary guidance, or scaffold behavior changes | Keep separate from the upstream template-maintainer root `AGENTS.md`; existing solution-owned `AGENTS.md` files are preserved by update helpers unless they still carry the generated marker |
| Codex custom agents and workflow skills | This template or solution repo | `agent-configs/codex/agents/` and `agent-configs/codex/skills/` source; `.codex/agents/*.toml` and `.agents/skills/dl-*/SKILL.md` generated targets | Codex phase roles, discoverable workflow routing, and subagent handoff guidance | Solution repo maintainers | Codex role behavior, workflow behavior, scaffolding, or discovery semantics change | Author standalone agent TOML and repo skills directly; run `scripts/delorean/check-codex-assets.sh` so deprecated `.codex/prompts/` and Markdown role adapters cannot pass |

## Folder Meanings

`architecture_docs/` contains shared architecture guidance copied from
`delorean_architecture` into generated solution repos. Use
[architecture-docs.md](architecture-docs.md) to find the generated lookup
catalogs and indexes, and reference reusable standards, patterns, controls,
baselines, templates, and reference architecture guidance by ID and title.

`docs/templates/` contains local templates for solution-facing artifacts, such
as OpenSpec, design notes, evidence, and repo checklists. Reusable architecture
templates live under `architecture_docs/templates/` in generated solution repos.

`PAT-*` documents contain implementation and design patterns copied from
`delorean_architecture` into generated solution repos. Patterns explain how to
apply standards in code and what tests, files, evidence, and stop conditions
apply.

`BAS-*` documents compose reusable controls into app-type or service-context
profiles. `GC-WEB-*` and other control namespace documents define reusable
assessable expectations. Solution repos record local assessment status,
evidence, deferred controls, and exceptions in evidence, PR notes, ADRs, or
baseline assessment records instead of editing the reusable source docs.

`delorean/templates/` contains templates for Delorean process records, such as approval responses and waivers.

OpenSpec owns functional requirements and proposed change planning, including implementation, review, and verification checklist state in `tasks.md`. Delorean owns verification evidence, approval, waivers, release readiness, standards expectations, agents, skills, hooks, and reference guidance.
